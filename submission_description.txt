Transaction Integrity Eval tests whether AI coding agents keep payment and ledger invariants intact (no double charges, no over-refunds, balances that always match their receipts and events) when the same request is retried, runs on several workers at once, or fails halfway through. It has 14 Python/SQLite tasks with withheld behavioral pytest graders, including a race probe that pauses one database connection before its first write while another commits, plus ablation tasks where the concurrency requirement is only implied. Across 147 Claude Code trials on Claude Opus 5.5, Sonnet 5.5 and Haiku 5.5, 145 passed and every race test passed. The two failures were transaction-lifecycle bugs (an early return that left a write transaction open, and a rollback helper that committed a partial write), showing that the models reliably knew to lock but did not always close the transaction correctly on every exit path.
